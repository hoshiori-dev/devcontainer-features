# GitHub Platform Settings

Read this before changing anything on the remote repository, when a merge is blocked for a reason no check explains, or
when a setting below changes. Remote settings are maintainer actions: agents read them back, never change them
(`.agents/knowledge/agent-authority.md`).

readable by API) · enforcement tier: rulesets available (public repository). The readbacks of Actions permissions,
branch protection, code security, and `security_and_analysis` need a token with admin access to the repository; the
default agent token gets 403 or an empty field there, so without one verify those rows in the UI. Organization issue

GitHub adds two parameters to the ruleset's pull-request rule on its own; they are expected in a readback, not drift:

- `require_extra_approval_for_unattributed_changes: true` — one approval more than configured when Copilot opens a pull
  request under its own app identity rather than on behalf of a person (public preview, on by default). No pull request
  here is opened that way, so the required approvals stay 0.
- `allowed_merge_methods: [merge, squash, rebase]` — the repository setting allows only squash, so squash is the only
  method that can merge.
