# Proposal

Implements [#155](https://github.com/hoshiori-dev/devcontainer-features/issues/155).

## Why

Many CI pipelines and pre-commit configurations still run Gitleaks, and a developer who wants the same findings before
pushing needs the same tool, at the same version, inside the dev container. Gitleaks is in maintenance mode (its README:
feature complete, security patches only, the author's focus moved to Betterleaks), so the feature exists for that
parity, says so, and points new setups to the `betterleaks` feature the collection already offers.

## What Changes

- A new feature `gitleaks` installs the `gitleaks` executable from upstream's verified GitHub release archives, on
  `PATH` for every user of the container, at the release its `version` option names or the latest release.
- The feature is installable twice on the same image, with the same or a different `version`.
- The feature configures nothing: it writes no scan configuration, baseline, or pre-commit hook, and sets no environment
  variable.
- The feature's `NOTES.md`, and so its generated README, states that upstream is in maintenance mode and that the
  feature exists for parity with pipelines that still run Gitleaks, and recommends the `betterleaks` feature for new
  setups.
- `test/gitleaks/` tests the feature on the images and architectures its compatibility list names.
- The root `README.md` gains the feature's row in its generated list, and `README.zh.md` carries the same row in
  Chinese.

## Capabilities

### New Capabilities

- `gitleaks`: installing the Gitleaks secrets scanner, choosing its version, verifying the download, installing twice,
  and failing on unsupported platforms or failed verification.

### Modified Capabilities

None.

## Impact

- Feature ids touched: `gitleaks`, new at version `1.0.0`.
- Files: `src/gitleaks/` (`devcontainer-feature.json`, `install.sh`, `NOTES.md`, and `README.md` generated by
  `just docs`); `test/gitleaks/` (`test.sh`, `duplicate.sh`, `checks.sh`, `scenarios.json` with its scenario scripts,
  `compatibility.json`); the root `README.md` (its generated feature list) and `README.zh.md` (the translated row).
- `test/canary.json` is not touched: canary membership is left to the maintainer.
- Network at build time: `github.com` and the host GitHub's release downloads redirect to (design.md, URL inventory),
  plus the image's configured package repositories when a prerequisite is missing; nothing at container start.
- CI: the PR runs the feature's container tests on every image and architecture of its compatibility list and its
  scenarios on both architectures, through the existing jobs; no workflow changes.
- Security: upstream publishes a checksum file and no signature, so the archive is verified against the checksum file,
  which relies on TLS alone; the delta spec states it.

## Acceptance

**Becomes true:**

- Every scenario in `specs/gitleaks/spec.md` that a successful container build can show holds on every image and
  architecture in `test/gitleaks/compatibility.json`, exercised by `test.sh`, `duplicate.sh`, and the scenarios; every
  other scenario holds in the manual check design.md (Goals) names for it, run once. Each result is recorded in the PR's
  Validation section.
- `test/gitleaks/compatibility.json` lists exactly the images and architectures planned in design.md (Supported images).
- `src/gitleaks/devcontainer-feature.json` has version `1.0.0`, and `src/gitleaks/README.md` and the root `README.md`
  are what `just docs` generates.
- `src/gitleaks/NOTES.md` states the maintenance mode, the parity purpose, and the recommendation of `betterleaks`.
- `README.zh.md` holds the translated row for `gitleaks` in its feature list.
- `just test gitleaks` and `just test-scenarios gitleaks` pass locally, and the PR's container test jobs pass on amd64
  and arm64.

**Stays true:**

- The feature has no option that takes a credential or token, writes no file under a user's home directory, and sets no
  container environment variable.
- The feature declares no `mounts`, `capAdd`, `privileged`, `securityOpt`, `init`, `entrypoint`, `dependsOn`,
  `installsAfter`, or lifecycle command.
- No file outside `src/gitleaks/`, `test/gitleaks/`, the root `README.md`, `README.zh.md`, and this change changes.
- `just check` passes, and every required check passes on this PR.
