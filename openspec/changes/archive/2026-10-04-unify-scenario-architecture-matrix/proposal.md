# Proposal

## Why

CI declares a dedicated arm64 scenario job for glab alongside a shared amd64 scenario matrix. This duplicates workflow
structure, and the scenario image validator checks only amd64 even when CI also runs arm64.

Issue: [#65](https://github.com/hoshiori-dev/devcontainer-features/issues/65).

## What Changes

- Feature scenario architectures are declared in test configuration and represented in the shared CI matrix.
- Glab retains its existing amd64 and arm64 coverage without a dedicated workflow job; other features retain their
  existing amd64 scenario coverage.
- Validation checks scenario image compatibility for every declared scenario architecture, including other in-repo
  features installed by the scenario.
- Testing documentation and the CI job map describe the shared architecture-aware scenario jobs.

## Capabilities

### New Capabilities

None. This is a CI and test infrastructure change with `skip_specs: true`.

### Modified Capabilities

None. Feature installation contracts and supported image/architecture pairs remain unchanged.

## Impact

- Implementation scope: `.github/workflows/ci.yml`, `scripts/affected.ts` documentation, `scripts/lib/repo.ts`,
  `scripts/lib/repo_test.ts`, `scripts/validate.ts`, `scripts/checks_test.ts`, `test/compatibility.schema.json`,
  `test/glab/compatibility.json`, `.agents/knowledge/testing.md`, and `.agents/knowledge/github/checks.md`.
- Feature id touched: `glab`, through its test configuration only. No version bump is needed: its supported
  image/architecture pairs and published files do not change.
- No new dependencies, runner architectures, workflow permissions, required-check settings, or release changes.

## Acceptance

**Becomes true:**

- The shared scenario matrix emits feature, architecture, and runner entries from declared test configuration; the
  workflow has no glab-specific scenario job or feature-name condition.
- An omitted scenario architecture declaration produces one amd64 entry; glab's declaration produces one amd64 and one
  arm64 entry on the corresponding native runners.
- Validation rejects empty, duplicate, and unknown scenario architectures and names the incompatible architecture when
  an image lacks support in the owner or another in-repo feature installed by a scenario.
- Matrix and validation unit tests cover defaults, dual-architecture selection, incompatible images, and an empty
  affected-feature selection. `just check` passes.
- CI runs all eight existing glab scenarios successfully on both amd64 and arm64; results are recorded in the PR's
  Validation section with the run link.
- The testing guide and CI job map match the resulting workflow and configuration.

**Stays true:**

- Existing affected-feature selection rules remain unchanged; a selection with no affected features produces no scenario
  jobs. Features without scenarios produce no scenario jobs.
- Other features' scenario counts and all autogenerated and duplicate image/architecture test pairs remain unchanged.
- Global scenarios remain amd64; `build` scenarios retain their existing image compatibility validation exemption.
- The scenario matrix still rejects more than 256 entries, counting architecture expansion.
- `ci-gate` depends on the shared scenario jobs and fails on a failed or cancelled job.
- Feature artifacts, versions, supported image/architecture pairs, release configuration, and repository settings remain
  unchanged.
