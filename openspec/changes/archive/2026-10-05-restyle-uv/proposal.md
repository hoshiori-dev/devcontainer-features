# Proposal

## Why

The uv feature's scripts and tests predate `.agents/knowledge/shell-style.md`, and the #52 audit confirmed problems in
them that make the feature harder to audit and to debug: package-manager failures end the build without a message from
the feature, a failing `sha256sum` is reported as a checksum mismatch against an empty digest, `echo` under dash
rewrites backslashes in the invalid option values that failure messages quote, `fail` depends on a global `IFS` reset,
the messages carry the prefix `uv feature:` and give no fix, several image-changing steps log nothing, and the tests
re-execute themselves under a bash they install into the Alpine image under test. Implements
https://github.com/hoshiori-dev/devcontainer-features/issues/80, part of
https://github.com/hoshiori-dev/devcontainer-features/issues/52.

## What Changes

- `src/uv/install.sh` and the volume-repair script follow the shell style guide, including readonly constants for every
  external URL and every path the feature creates or changes, a `main` that lists the steps, and long options wherever
  every implementation that runs a command has them; every deliberate deviation is marked with its reason.
- The source of the volume-repair script is `src/uv/repair_volume.sh`; it is still installed as
  `/usr/local/share/uv-feature/repair-volume`, which `onCreateCommand` runs.
- Every message starts with `uv:` (`uv: error:` for a failure, `uv: warning:` for the repair warning), starts in lower
  case, has no trailing period, and is printed verbatim; every failure the developer can fix says how to fix it.
- A failing package-manager command, a failing `sha256sum`, and a freshly installed `uv` that cannot report its version
  each fail the build with a message of their own.
- Every step that changes the image or uses the network logs one line saying what it does, from where, and to where.
- A group `uv` with several other accounts is reported with all of them on one line.
- The tests follow the guide: the scripts that run on `alpine:3.24` are POSIX `sh` with a feature-local stand-in for the
  test library, the others are bash; no test installs bash, check labels state behavior in the spec's words, expected
  values are literals unless they must be computed at run time, and setup is not reported as a check.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. No behavior a Requirement of `openspec/specs/uv/spec.md` covers changes, so the change sets `skip_specs: true`.

## Impact

- Feature `uv`: version 1.0.0 → 1.0.1, a PATCH bump (`.agents/knowledge/feature-authoring.md`, Versions): the change
  fixes failure reporting and message text and changes no option, supported image, install location, or result of a
  successful install.
- Files: `src/uv/install.sh`, `src/uv/repair-volume.sh` (renamed to `src/uv/repair_volume.sh`),
  `src/uv/devcontainer-feature.json` (version only), `test/uv/*.sh`, a new `test/uv/checks.sh`, and
  `test/uv/changed_uid/Dockerfile`. `src/uv/NOTES.md` quotes no message and stays unchanged; `src/uv/README.md` is
  regenerated by `just docs` with no content change.
- CI also re-tests hf-cli, which installs after uv, and the global scenarios.

## Acceptance

### Becomes true

- `shellcheck` and `shellcheck -o require-variable-braces,require-double-brackets` report nothing on `src/uv/*.sh` and
  `test/uv/*.sh`.
- `src/uv/install.sh` and `src/uv/repair_volume.sh` follow `.agents/knowledge/shell-style.md`; each deviation from it
  has a comment on the line above giving the reason.
- Every line `install.sh` prints itself starts with `uv:`, and every failure line with `uv: error:`; every message
  starts in lower case and has no trailing period; every failure the developer can fix ends with `; <how to fix it>`.
- The repair warning starts with `uv: warning: /var/lib/uv:`, names the reason, and points to the feature's NOTES.md.
- An invalid `version` or `toolsToInstall` entry that contains a backslash appears unchanged in the failure message.
- A failing package-manager command fails the build with a `uv: error:` message naming the packages and the package
  manager.
- A failing `sha256sum` fails the build with its own error instead of a checksum mismatch.
- A freshly installed `uv` that cannot report its version fails the build.
- A group `uv` with several other accounts fails the build with one message line naming all of them.
- Every step that changes the image or uses the network logs one line before it runs.
- `src/uv/devcontainer-feature.json` has version `1.0.1`.
- `test/uv/test.sh`, `duplicate.sh`, `pinned_release.sh`, and `changed_uid.sh`, which run on `alpine:3.24`, are POSIX
  `sh` with `set -eu` and use a POSIX stand-in for the test library; `tools.sh`, `runtime_python.sh`,
  `repair_volume.sh`, and `minimal_image.sh` are bash with `set -euo pipefail`; no test script and no test Dockerfile
  installs bash.
- `just check`, `just test uv`, `just test-scenarios uv`, `just test-scenarios hf-cli`, and `just test-global` pass.

### Stays true

- Download sources, TLS settings, and checksum verification are unchanged: the feature accesses exactly the URLs it
  accessed before, with the same transport restrictions, and verifies the release archive against the same published
  SHA-256 before installing anything; no signature check is added or removed, and no installer script runs.
- Every Requirement and Scenario of `openspec/specs/uv/spec.md` still holds.
- Installing the feature twice succeeds as "Install twice" states; `test/uv/duplicate.sh` passes.
- The options keep their names, types, and defaults, and every option value is accepted or rejected exactly as before;
  an explicitly empty `version` still fails.
- An input with several problems fails on the same problem first as before.
- Installed paths, `/etc/profile.d/uv.sh` (byte for byte), `containerEnv`, `mounts`, `installsAfter`, and
  `onCreateCommand` are unchanged.
- The volume-repair script exits 0 on every path, so dev container creation continues as "Repair a volume that no longer
  fits the remote user" states.
- An existing `/usr/local/bin/uv` that cannot report its version is replaced, as before, instead of failing the install.
- A checksum file that writes the digest in upper case is still accepted.
- `test/uv/compatibility.json` and `test/uv/scenarios.json` are unchanged.
