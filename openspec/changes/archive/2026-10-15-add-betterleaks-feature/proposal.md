# Proposal

Implements [#152](https://github.com/hoshiori-dev/devcontainer-features/issues/152).

## Why

Betterleaks is the secrets scanner the Gitleaks maintainers now develop as its successor, and a dev container that scans
its workspace or Git history for leaked credentials needs it on `PATH`. Installing it by hand in every Dockerfile
repeats the download, the architecture mapping, and the checksum check, and projects that pin different releases drift
apart; the collection already solves the same problem for `glab` and should offer the same for Betterleaks.

## What Changes

- A new feature `betterleaks` installs the `betterleaks` executable from upstream's verified GitHub release archives, on
  `PATH` for every user of the container, at the release its `version` option names or the latest stable release. A
  pre-release upstream publishes, such as a `2.0.0` release candidate, is installable only when named explicitly;
  `latest` never resolves to one.
- The feature is installable twice on the same image, with the same or a different `version`.
- The feature configures nothing: it writes no scan configuration, baseline, or pre-commit hook, and sets no environment
  variable; scanning options stay with the user.
- `test/betterleaks/` tests the feature on the images and architectures its compatibility list names.
- The root `README.md` gains the feature's row in its generated list, and `README.zh.md` carries the same row in
  Chinese.

## Capabilities

### New Capabilities

- `betterleaks`: installing the Betterleaks secrets scanner, choosing its version, verifying the download, installing
  twice, and failing on unsupported platforms or failed verification.

### Modified Capabilities

None.

## Impact

- Feature ids touched: `betterleaks`, new at version `1.0.0`.
- Files: `src/betterleaks/` (`devcontainer-feature.json`, `install.sh`, `NOTES.md`, and `README.md` generated by
  `just docs`); `test/betterleaks/` (`test.sh`, `duplicate.sh`, `checks.sh`, `scenarios.json` with its scenario scripts,
  `compatibility.json`); the root `README.md` (its generated feature list) and `README.zh.md` (the translated row).
- `test/canary.json` is not touched: canary membership is left to the maintainer.
- Network at build time: `github.com` and the host GitHub's release downloads redirect to (design.md, URL inventory),
  plus the image's configured package repositories when a prerequisite is missing; nothing at container start.
- CI: the PR runs the feature's container tests on every image and architecture of its compatibility list and its
  scenarios on both architectures, through the existing jobs; no workflow changes.
- Security: upstream signs its checksum list with a Sigstore bundle, and this change verifies the archive against the
  checksum list only, leaving the signature unverified; the delta spec states the risk, and design.md records the signer
  identity a follow-up would pin. The maintainer approves or rejects that bound at the package gate.

## Acceptance

**Becomes true:**

- Every scenario in `specs/betterleaks/spec.md` that a successful container build can show holds on every image and
  architecture in `test/betterleaks/compatibility.json`, exercised by `test.sh`, `duplicate.sh`, and the scenarios;
  every other scenario holds in the manual check design.md (Goals) names for it, run once. Each result is recorded in
  the PR's Validation section.
- `test/betterleaks/compatibility.json` lists exactly the images and architectures planned in design.md (Supported
  images).
- `src/betterleaks/devcontainer-feature.json` has version `1.0.0`, and `src/betterleaks/README.md` and the root
  `README.md` are what `just docs` generates.
- `README.zh.md` holds the translated row for `betterleaks` in its feature list.
- `just test betterleaks` and `just test-scenarios betterleaks` pass locally, and the PR's container test jobs pass on
  amd64 and arm64.

**Stays true:**

- The feature has no option that takes a credential or token, writes no file under a user's home directory, and sets no
  container environment variable.
- The feature declares no `mounts`, `capAdd`, `privileged`, `securityOpt`, `init`, `entrypoint`, `dependsOn`,
  `installsAfter`, or lifecycle command.
- No file outside `src/betterleaks/`, `test/betterleaks/`, the root `README.md`, `README.zh.md`, and this change
  changes.
- `just check` passes, and every required check passes on this PR.
