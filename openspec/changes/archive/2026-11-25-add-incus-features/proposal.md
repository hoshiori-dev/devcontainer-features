# Proposal

Implements [#211](https://github.com/hoshiori-dev/devcontainer-features/issues/211).

## Why

Developers who work on infrastructure code, image definitions, or software that must run on several distributions need
system containers next to their source: full distributions with their own init, started in seconds. Incus is the
community's manager for them, and distrobuilder builds the images they start from. The collection has a feature for
neither, and both are awkward in a dev container: Incus is packaged for systemd and needs settings a container does not
have by default, and distrobuilder is published as source only and does not start in a default container.

## What Changes

- A new feature `incus` installs Incus from the Zabbly package repository, whose signing key it pins by fingerprint,
  declares the container privileged with an init process, and starts the Incus daemon at every container start. The
  remote user launches and manages instances that run inside the dev container. The daemon's data lives on one named
  volume and survives a rebuild.
- A new feature `lxc-distrobuilder` builds distrobuilder from upstream's signed release source with a checksum-verified
  Go toolchain that it removes again, and installs it with the tools it runs. It declares the capability `SYS_ADMIN` and
  the security option `apparmor=unconfined`, which is enough to build container images; it does not declare the
  container privileged.
- The two features are independent: each installs and works without the other, and neither depends on or orders itself
  after the other.
- Both are installable twice on the same image, with the same or different options.
- `test/incus/` and `test/lxc-distrobuilder/` test the features on the images and architectures their compatibility
  lists name. No workflow, composite action, or script changes.
- The root `README.md` gains both features' rows in its generated list, and `README.zh.md` carries the same rows in
  Chinese.

## Capabilities

### New Capabilities

- `incus`: installing Incus from the Zabbly repository at a chosen channel, with or without virtual machine support;
  starting the daemon at every container start in a privileged container; the first initialization; the remote user's
  access; the persistent volume; the start record and check; and installing twice.
- `lxc-distrobuilder`: selecting a distrobuilder release, verifying and building its source, the tools it runs and the
  optional ones for virtual machine images and Windows media, the container privileges it declares, and installing
  twice.

### Modified Capabilities

None.

## Impact

- Feature ids touched: `incus` and `lxc-distrobuilder`, both new at version `1.0.0`.
- Files: `src/incus/` (`devcontainer-feature.json`, `install.sh`, `scripts/`, `NOTES.md`, and `README.md` generated by
  `just docs`) and `src/lxc-distrobuilder/` (the same without `scripts/`); `test/incus/` and `test/lxc-distrobuilder/`
  (each `test.sh`, `duplicate.sh`, `scenarios.json` with its scenario scripts, and `compatibility.json`); the root
  `README.md` (its generated feature list) and `README.zh.md` (the translated rows).
- `test/canary.json` is not touched.
- Metadata of `incus`: `privileged`, `init`, one `mounts` entry (a named volume), `entrypoint`, `postStartCommand`, and
  `installsAfter` naming the external `common-utils` feature; no `capAdd`, `securityOpt`, `containerEnv`, or
  `dependsOn`.
- Metadata of `lxc-distrobuilder`: `capAdd` and `securityOpt`; no `privileged`, `init`, `mounts`, `entrypoint`,
  lifecycle command, `containerEnv`, `dependsOn`, or `installsAfter`.
- Network at build time: `incus` reaches `pkgs.zabbly.com` and the image's configured package repositories;
  `lxc-distrobuilder` reaches `github.com` with its release download redirects, `dl.google.com`, and the image's
  configured package repositories. Neither contacts the network at container start.
- CI: the PR runs both features' container tests through the existing jobs; no workflow changes. The jobs of `incus` run
  privileged containers and those of `lxc-distrobuilder` containers with `SYS_ADMIN`, as the features' metadata
  declares.
- Security: `incus` runs a privileged container in which members of the `incus-admin` group, the remote user among them,
  control a daemon that runs as root; `lxc-distrobuilder` gives the container `SYS_ADMIN` without an AppArmor profile.
  Both install software from outside the image's distribution: a third package repository, and source that is compiled
  at build time. The delta specs state the risks and their reasons, and the keys and checksums each download is verified
  against.

## Acceptance

**Becomes true:**

- Every scenario in `specs/incus/spec.md` and `specs/lxc-distrobuilder/spec.md` that a successful container build or a
  scenario script can show holds on every image and architecture in the feature's `compatibility.json`, exercised by
  `test.sh`, `duplicate.sh`, and the scenarios; every other scenario holds in the check design.md (Tests) names for it,
  run once. Each result is recorded in the PR's Validation section.
- Each `compatibility.json` lists exactly the images and architectures planned in design.md (Supported images).
- Both `devcontainer-feature.json` files have version `1.0.0`, and both features' `README.md` and the root `README.md`
  are what `just docs` generates.
- Each feature's `NOTES.md` states what its delta spec's requirements say `NOTES.md` states (the accepted risks, the
  documented limits, and what needs a privileged container).
- `README.zh.md` holds the translated rows for both features in its feature list.
- `just test` and `just test-scenarios` pass locally for both features, and the PR's container test jobs pass on amd64
  and arm64.

**Stays true:**

- Neither feature weakens certificate, signature, or checksum verification of anything it downloads, carries a hash tied
  to one upstream version, or contacts the network at container start.
- `incus` adds no package repository other than the Zabbly one and no signing key other than the pinned one;
  `lxc-distrobuilder` adds no package repository or signing key to the image and leaves no Go toolchain in it.
- `lxc-distrobuilder` declares no `privileged`, `mounts`, `entrypoint`, or lifecycle command.
- No file outside `src/incus/`, `src/lxc-distrobuilder/`, `test/incus/`, `test/lxc-distrobuilder/`, the root
  `README.md`, `README.zh.md`, and this change changes; in particular nothing under `.github/` or `scripts/`.
- `just check` passes, and every required check passes on this PR.
