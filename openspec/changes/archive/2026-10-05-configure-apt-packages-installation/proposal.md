# Proposal

Implements [#55](https://github.com/hoshiori-dev/devcontainer-features/issues/55).

## Why

Developers need explicit installation controls instead of the single packages option. This change extends the completed
apt-packages feature at 1.0.0, preserving the default installation path and the package manager's native resolution.

## What Changes

- Extend apt-packages with selectable recommended dependencies, metadata refresh, cleanup, and bounded network timeout;
  its delta spec owns the option contracts and interactions.
- Keep default behavior and support coverage; retain existing package syntax, trust policy, and noninteractive
  installation.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- apt-packages: selectable installation controls and per-invocation behavior when installed twice.

## Impact

- Feature ids touched: apt-packages changes from 1.0.0 to 1.1.0 (MINOR).
- Implementation after approval: src/apt-packages/install.sh, devcontainer-feature.json, NOTES.md, and README.md
  generated by just docs; feature-specific scenario and direct tests. No compatibility, harness, workflow, or
  devcontainer configuration changes.
- This commit carries planning only. The metadata version and implementation are updated together after the package gate
  closes; the current artifact is not claimed to implement the new controls.

## Acceptance

**Becomes true:**

- Every scenario in this delta passes on each supported package-manager generation, with the test, image, architecture,
  and result recorded in the PR. The design's verification bounds determine scenario/direct coverage.
- Every declared option agrees between the delta spec, feature metadata, NOTES.md, and the generated README; the feature
  metadata has version 1.1.0.
- just check, just test apt-packages, and just test-scenarios apt-packages pass, with meaningful checks of option
  effects and repeated installation.

**Stays true:**

- Default installation retains baseline behavior and valid empty lists remain no-ops.
- Signature and TLS verification, trusted repository settings, noninteractive installation, package syntax, and native
  version/provider resolution retain their baseline contracts.
- No feature option adds repositories or keys, permits conflict-driven removal, or overrides package holds.
- Existing compatibility images and architectures stay supported; unrelated caches, installed-package databases, and
  system configuration files are not removed by cleanup.
- Only the named feature, its tests, and its OpenSpec change are touched; no privileges, mounts, lifecycle hooks, or
  feature dependencies are introduced.
