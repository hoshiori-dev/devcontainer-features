# Proposal

Implements [#74](https://github.com/hoshiori-dev/devcontainer-features/issues/74), part of
[#52](https://github.com/hoshiori-dev/devcontainer-features/issues/52).

## Why

The deno feature predates `.agents/knowledge/shell-style.md`, so its install script and tests do not read the way the
guide asks shipped scripts and tests to read. The #52 audit also confirmed, for this feature, failures that surface late
or with a misleading message, implicit word splitting, and tests whose intent is hidden behind defensive handling.
Developers who audit the feature before trusting it, and those who fix their configuration after a failed build, need
the script, its logs, and its tests to state plainly what happens.

## What Changes

- `src/deno/install.sh` and every script under `test/deno/` follow the shell style guide.
- Log lines start with `deno:` and failure messages with `deno: error:`; every failure the developer can fix states the
  reason and how to fix it, and every step that uses the network or changes the image logs one line.
- A missing `groupadd` or `usermod` that a non-root remote user's group setup needs fails before package installation or
  downloads, with a message naming the command, instead of a raw `command not found` after the download.
- A failure while computing a checksum stops at its own error instead of surfacing as a checksum mismatch, and the line
  naming the version `latest` resolved to goes to stdout like every other log line.
- Tests state each behavior in the spec's words, and the host-side group conflict test covers the group commands.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `deno`: Requirement "Shared location for global tools" states when `groupadd` and `usermod` are required and how their
  absence fails.

## Impact

- Feature id `deno`: PATCH bump, `1.0.0` to `1.0.1`. Per `.agents/knowledge/feature-authoring.md` (Versions), every
  change under `src/deno/` bumps the version; this one is a fix: no option, default, supported image, architecture, or
  install location changes, and on the supported images nothing that installs today fails and nothing that fails today
  installs; the group command check only moves an existing failure earlier.
- Files: `src/deno/install.sh`, `src/deno/devcontainer-feature.json` (version only), `src/deno/NOTES.md` (group
  commands), `src/deno/README.md` (regenerated by `just docs`), and the scripts under `test/deno/`. No change to
  `test/deno/compatibility.json`, `test/deno/scenarios.json`, the scenario Dockerfiles, other features, scripts, or CI.

## Acceptance

### Becomes true

- `shellcheck -o require-variable-braces,require-double-brackets` reports nothing for `src/deno/install.sh` and every
  `test/deno/*.sh`; `just check` passes.
- Every line the install script itself logs starts with `deno:` and a space, and every failure message it prints with
  `deno: error:` and a space; output of the commands it runs is not prefixed.
- The delta scenarios "Group command missing" and "Group prepared in the image" pass in `test/deno/group_conflicts.sh`,
  run by hand, together with its existing cases.
- Each failure scenario of the deno spec, run by hand as the archived design of the feature's first change lists them,
  fails with a message holding the content its scenario names; the image, input, exit status, and message of each run
  are recorded in the PR.
- `just test deno` and `just test-scenarios deno` pass.
- `src/deno/devcontainer-feature.json` has version `1.0.1`, and `src/deno/README.md` matches `just docs`.

### Stays true

- No change to download sources, TLS requirements, checksum verification, or signature verification: the same URLs,
  HTTPS on every hop, and both checksum files required and checked before extraction and installation.
- Every existing Requirement and Scenario of the deno spec still holds, as modified by this change's delta.
- The feature still installs twice on the same image, with the same or a different `version`.
- `version` accepts exactly `latest` and `MAJOR.MINOR.PATCH`; an explicitly empty value still fails.
- Option names, types, defaults, metadata other than `version`, supported images, and installed paths are unchanged.
- `/etc/profile.d/deno.sh` keeps its exact content: the body the script writes is unchanged in the diff.
