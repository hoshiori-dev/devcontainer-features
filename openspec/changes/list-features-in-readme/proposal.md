# Proposal

Implements [#39](https://github.com/hoshiori-dev/devcontainer-features/issues/39).

## Why

The root `README.md` is where a consumer looks for what the collection offers. Its "Features" section still reads "No
features have been published yet", and nothing in the harness asks a feature change to update it. Features would ship
while the list stays stale. Per-feature READMEs (`src/<id>/README.md`) are generated by `just docs`, but no tool
maintains the root list.

## What Changes

- `.agents/knowledge/feature-authoring.md` states the convention:
  - The pull request that adds a feature adds a row for it under "Features" in the root `README.md`: the feature id,
    linked to `src/<id>/`, and a one-sentence description. The first such row replaces the "No features have been
    published yet" line.
  - A rename updates the row.
  - Retiring a feature removes its row.
- The `tasks` rule in `openspec/config.yaml` for a feature change also covers the root `README.md` row when a feature is
  added, renamed, or retired, so OpenSpec's task instructions carry it.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. This change edits the harness only (`skip_specs: true`).

## Impact

- Files: `.agents/knowledge/feature-authoring.md`, `openspec/config.yaml`.
- Feature ids touched: none, so no version bump.
- The open feature drafts carry the row in their own proposals and pull requests.
- CI: nothing selects container tests. `just spec-check` validates that the edited rule still reaches OpenSpec.

## Acceptance

**Becomes true:**

- `feature-authoring.md` states that adding, renaming, and retiring a feature each update the root `README.md`
  "Features" row, in the form described under What Changes.
- `openspec instructions tasks` for a change prints the edited `tasks` rule, which names the root `README.md` row.
  Checked by running it against any active change.

**Stays true:**

- `src/<id>/README.md` is still generated by `just docs` and never edited by hand, and `just docs-check` behaves as
  before.
- `git diff --name-only origin/main...HEAD` lists only `.agents/knowledge/feature-authoring.md`, `openspec/config.yaml`,
  and files under `openspec/changes/list-features-in-readme/`.
- `just check` passes, including the check that every rule in `openspec/config.yaml` reaches OpenSpec, and every
  required check passes on this PR.
