# Proposal

Implements [#22](https://github.com/hoshiori-dev/devcontainer-features/issues/22).

## Why

Developers need explicit installation controls instead of the single packages option. This change extends the baseline
approval package and implementation in ../add-apk-packages-feature/, preserving the default installation path and the
package manager's native resolution.

## What Changes

- Extend apk-packages with selectable metadata refresh, cleanup, bounded network timeout, and selected-package upgrades;
  its delta spec owns the option contracts and interactions.
- Keep default behavior and support coverage; retain existing package syntax, trust policy, and noninteractive
  installation.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- apk-packages: selectable installation controls and per-invocation behavior when installed twice.

## Impact

- Feature ids touched: apk-packages is still unpublished: the combined PR first publishes version 1.0.0 with both the
  baseline and this extension. No separate version has been released.
- Implementation after approval: src/apk-packages/install.sh, devcontainer-feature.json, NOTES.md, and README.md
  generated by just docs; feature-specific scenario and direct tests. No compatibility, harness, workflow, or
  devcontainer configuration changes.
- This commit carries planning only. The metadata version and implementation are updated together after the package gate
  closes; the current artifact is not claimed to implement the new controls.

This delta depends on the ADDED requirements in add-apk-packages-feature. Apply that baseline before this MODIFIED
delta. Existing code, completed tasks, and validation evidence cover only the baseline; this change has no tasks until
its expanded package is approved.

## Acceptance

**Becomes true:**

- Every scenario in this delta passes on each supported package-manager generation, with the test, image, architecture,
  and result recorded in the PR. The design's verification bounds determine scenario/direct coverage.
- Every declared option agrees between the delta spec, feature metadata, NOTES.md, and the generated README; the first
  published feature metadata has version 1.0.0.
- just check, just test apk-packages, and just test-scenarios apk-packages pass, with meaningful checks of option
  effects and repeated installation.

**Stays true:**

- Default installation retains baseline behavior and valid empty lists remain no-ops.
- Signature and TLS verification, trusted repository settings, noninteractive installation, package syntax, and native
  version/provider resolution retain their baseline contracts.
- No feature option adds repositories or keys, permits conflict-driven removal, or overrides package holds.
- Existing compatibility images and architectures stay supported; unrelated caches, installed-package databases, and
  system configuration files are not removed by cleanup.
- Only the named feature, its tests, and its OpenSpec change are touched; no privileges, mounts, lifecycle hooks, or
  feature dependencies are introduced.
